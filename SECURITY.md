# Security Policy

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security of our project very seriously. If you discover a security vulnerability, please report it responsibly through private channels. **Do not disclose security vulnerabilities publicly** until a patch has been released.

### How to Report

* **Email:** Send your findings directly to **arun79525@gmail.com**.
* **Preferred Language:** English / Hindi
* **Encryption:** If your finding is extremely sensitive, please request our PGP public key via email before sharing the payload or exploit details.

### What to Include in Your Report

To help us triage and fix the vulnerability as quickly as possible, please provide:
1. **Type of vulnerability** (e.g., SQL Injection, XSS, Remote Code Execution, Authentication Bypass).
2. **Full paths of source file(s)** related to the manifestation of the issue.
3. **Step-by-step instructions** or a Proof of Concept (PoC) script to reproduce the issue safely.
4. **Impact assessment** explaining what an attacker could achieve by exploiting this flaw.

---

## Disclosure Policy

When you report a vulnerability to us, we follow these commitments:
* **Acknowledgment:** You will receive an initial response to your email within **24 to 48 hours**.
* **Updates:** We will keep you informed of our progress regarding the vulnerability triage, patch development, and release timeline.
* **Public Credit:** Once the patch is deployed, we publicly acknowledge and thank reporters for their responsible disclosure (unless you prefer to remain anonymous).

Thank you for helping keep this project and our users safe!
